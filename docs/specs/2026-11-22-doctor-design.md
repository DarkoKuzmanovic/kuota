# Offline doctor — approved design

**Approval:** owner request, 2026-11-22, for GitHub issue #8. This is an offline CLI slice only; it does not approve UI provenance/retry fields, release, or issue closure.

`kuota doctor` is a separate human-facing command, not called by the widget. `status` remains the lightweight account summary. Doctor never requests providers, refreshes credentials, writes credentials, or changes widget state. It emits a closed set of classifications, not auth values, account IDs, raw errors, request payloads, or environment dumps. Its output is subject to the central redaction/secret scanner. Extra command arguments are rejected without echo.

The report enumerates the collector provider IDs and default opt-in configuration. Each provider reports the credential source the existing read-only discovery would select and a local classification (present, missing, malformed, unsafe, expired, or unavailable). A locally present credential is not proof of server acceptance. Selection uses the provider readers and their actual precedence; no refresh is called. Firefox diagnostics must not create a copy of a cookie database or mutate browser state. If the active browser database cannot be safely read without a write, report unavailable rather than guessing. Environment fallbacks never print their values.

Report Kuota's cache directory and credentials store safety, the collector and Claude last-known-good records and Claude backoff sidecar. Cache records are successful observations, not the most recent refresh attempt: don't call cached data fresh or infer an attempt result. Report available record state and last-success age, and active backoff remaining, without raw records. Explain stale as retained last-known-good data: re-login will not help unless the state is auth-needed; investigate endpoint drift. Auth-needed uses the provider-specific login hint from the widget. Missing or invalid caches are identified without echoing input.

Check the fixed `/usr/bin/node` major version >=20, `/usr/bin/flock`, `/usr/bin/sqlite3`, curl, and trusted owner-only Kuota cache/config directories and 0600 credentials file. Missing directories/files are reported as missing, not created. The report identifies package/collector/schema versions where available; it does not invent a remote version or retry time.

Exit 0 only if every default-enabled provider has a locally usable source and required runtime/safety checks succeed; exit 1 for an unusable default provider or failed required check. Opt-in providers do not affect exit status. Locally expired Kuota OAuth with a refresh credential is reported expired but can be renewed on collection; its usability remains conditional and is not asserted as valid. An unknown/missing cached observation alone does not establish provider failure. Exit 2 rejects malformed invocation. No local diagnostic establishes live account health.

Tests use synthetic HOME and credentials, verify precedence and classifications, no credential leaks, no requests/refresh/writes, permissions/symlink handling, cache freshness semantics and fixed runtime outcomes. Acceptance gates run sequentially in a disposable synthetic environment with `dist` removed before each gate, followed by one real-HOME offline doctor run checked for secrets. Issue #8 is not closed by implementation; the later UI slice remains separate.
