# Offline doctor — approved design

**Approval:** owner request, 2026-11-22, for GitHub issue #8. This is an offline CLI slice only; it does not approve UI provenance/retry fields, release, or issue closure.

`kuota doctor` is a separate human-facing command, not called by the widget. `status` remains the lightweight account summary. Doctor never requests providers, refreshes credentials, writes credentials, or changes widget state. It emits a closed set of classifications, not auth values, account IDs, raw errors, request payloads, or environment dumps. Its output is subject to the central redaction/secret scanner. Extra command arguments are rejected without echo.

The report enumerates the collector provider IDs and default opt-in configuration. Each provider reports the credential source the existing discovery would select and a local classification (present, missing, malformed, unsafe, expired, or unavailable). Selection uses the actual provider readers and their precedence; no refresh is called. Firefox uses the collector's private 0700 temporary copy of `cookies.sqlite` and its WAL, and removes that copy afterwards; it does not write the browser database. A locally present credential is not proof of server acceptance, stated once as a footnote. Environment fallbacks never print their values.

Report Kuota's cache directory and credentials store safety, collector and Claude last-known-good records and the Claude backoff sidecar. These caches retain only successful observations, not the most recent refresh attempt: do not infer the current provider state. Claude's cache reader reconstructs `stale` for fallback use even though its stored observation was successful. Report that observation as `ok`, not as proof of a current stale result. For any available actual state, `ok` has no warning; `stale` explains retained data and endpoint drift rather than re-login; `auth-needed` uses the widget's provider login hint; `error` describes a failed provider without implicating other providers. Never print raw records or invent an attempt result.

Check the fixed `/usr/bin/node` major version >=20, `/usr/bin/flock`, `/usr/bin/sqlite3`, curl, and trusted owner-only Kuota cache/config directories and 0600 credentials file. Missing directories/files are reported as missing, not created. The report identifies package/collector/schema versions where available; it does not invent a remote version or retry time.

Exit 1 only for failed environment checks or version mismatch, unsafe permissions, malformed/unsafe credentials, or an available cached `stale`, `auth-needed` or `error` state. A provider without a credential and cached record is informational: report “not set up” and do not fail. Missing directories and files that collection can create are informational; an expired or locally unavailable source is reported without asserting server rejection. Existing Kuota caches store only successful records, so a current failed state cannot be determined from them; it must not be invented. Exit 2 rejects malformed invocation.

Tests use synthetic HOME and credentials, verify precedence and classifications, no credential leaks, no provider requests, refreshes, or credential writes, private Firefox-copy cleanup including WAL, permissions/symlink handling, cache freshness semantics and fixed runtime outcomes. Acceptance gates run sequentially in a disposable synthetic environment with `dist` removed before each gate, followed by one real-HOME offline doctor run checked for secrets. Issue #8 is not closed by implementation; the later UI slice remains separate.
